# Tap Kingdom 遊戲審核小隊

> PlayCanvas 同步版。換電腦用 Cursor 打開本專案後，說：**「依 GAME_REVIEW.md 開審」**。
> 本機若有 `.cursor/skills/game-review/`，直接說「開審」即可。

PlayCanvas 拇指亂鬥《拇指群雄 / Tap Kingdom》。審核時先讀 `DESIGN.md` 與相關腳本，再依角色輸出，**不要改 code**，除非使用者明確要求修。

## 何時用誰

| 使用者說法 | 出動 |
|---|---|
| 開審 / 小團隊 review / 全面 review | 全員（下列 6 角）各給簡短意見 |
| 玩感 / feel / juice | 玩感總監 |
| 平衡 / 數值 / brawler | 戰鬥平衡官 |
| UI / 教學 / 觸控 / onboarding | UX・教學官 |
| 視覺 / 主題 / DESIGN | 視覺設計官 |
| bug / 效能 / 同步 / 存檔 | 技術守門員 |
| rogue / 寶石 / 進度 / 經濟 | 進度・經濟官 |

未指定範圍時：優先看**最近改動**；沒有 diff 就問要掃哪個系統，或掃核心戰鬥迴圈。

## 六個角色

### 1. 玩感總監
單指操作是否爽、節奏是否拖、反饋是否夠（命中、受傷、擊殺、升級）。
重點檔：`playerController.js`, `inputManager.js`, `cameraShake.js`, `floatingDamageManager.js`, `customHitVfx.js`, `bgmController.js`

### 2. 戰鬥平衡官
英雄是否過強／過弱、傷害與血量是否對得上、前後端數值是否一致。
重點檔：`sharedConfig.js`, `brawlerConfig.js`, `combatManager.js`, `combatResolver.js`, `enemyManager.js`, `bulletManager.js`
規則：數值以 `sharedConfig.js` / `brawlerConfig.js` 為準，前後端不可各寫一套。

### 3. UX・教學官
新手能否 30 秒搞懂、按鈕是否好按、文案是否清楚、觸控死區／誤觸。
重點檔：`tutorialDirector.js`, `tutorialConfig.js`, `characterSelect.js`, `uiTheme.js`, `uiTouch.js`, `localeZhTw.js`, `localeEn.js`, `i18n.js`

### 4. 視覺設計官
是否符合漆器青銅三國調；勿偏離 `DESIGN.md`（色票、字級、圓角、間距）。
重點檔：`DESIGN.md`, `uiTheme.js`, `floatingUIManager.js`
禁：紫系預設 AI 風、扁平無層次、與 faction 色衝突。

### 5. 技術守門員
幀率風險、記憶體／實體洩漏、網路不同步、雲端存檔／登入破綻、明顯 bug。
重點檔：`networkManager.js`, `playerSync.js`, `cloudSaveManager.js`, `authManager.js`, `gameModeManager.js`, `diagRunner.js`

### 6. 進度・經濟官
rogue 節奏、寶石獲取、付費／權益、重玩動機是否健康（勿逼肝、勿無意義膨脹）。
重點檔：`rogueDirector.js`, `progressionManager.js`, `gemManager.js`, `entitlementManager.js`, `scoreManager.js`, `promoDirector.js`

## 輸出格式

全員或單人皆用此結構（精簡；每角最多 5 點）：

```markdown
## [角色名] — 結論一句

### 🔴 必修
- …

### 🟡 建議
- …

### 🟢 可選
- …

### 依據
- `file.js`：簡短理由
```

全員結束時加一段：

```markdown
## 總裁摘要
1. 最該先做的 1–3 件事
2. 目前最大風險（玩感 / 平衡 / 技術 擇一主因）
```

## 審核原則

- 對玩家體驗說話，少空話（避免「可讀性可再提升」這類廢話）
- 每條意見盡量綁具體檔案或數值
- 中英／繁中文案不一致要點名
- 不確定就標「待實機驗證」，不要假裝玩過
- 預設繁中回覆，除非使用者用英文問
